# Old ↔ New Clinical Dataset Mapping

**Purpose.** The contract that makes the frozen hand extraction and the new automated master comparable, and the procedure that turns that comparison into evidence for one claim: *the redesign did not change the evidence.* The comparison target is **old clinical vs new clinical** — the same studies under both processes (decision 4). It is not a clinical-vs-observational comparison.

**Sides.**

| | Old | New |
|---|---|---|
| Store | `data/Alcohol_Dataset.xlsx` (33), `data/Smoking_Dataset.xlsx` (4), `data/Opioid_Dataset.xlsx` (7) | `clinical_trials/outputs/clinical_master.csv` (48 expected) |
| Status | Frozen, read-only (decision 5) | Regenerated by the pipeline in `clinical_system_design.md` |
| Provenance | None archived — no request, no response, no model version, no prompt version, no date | Fully archived per article (`clinical_system_design.md` §1.4) |

The asymmetry in the last row is why this document exists. The frozen files cannot support a provenance claim of their own; the only rigorous role they can play is as the prior measurement against which the new one is checked.

**Output.** `clinical_trials/outputs/old_new_comparison_report.md`, produced by a deterministic script and read by a human. It is a gate step in `clinical_system_design.md` §9.3.

---

## 1. Scope of comparison

44 frozen rows against the new master. Four of the 48 new rows are the previously dropped alcohol studies and have no old counterpart by construction — they are reported, not compared.

Comparison runs on the **raw** frozen files against the **raw** master, before `_lib.clean()`. Cleaning applies transformations (`3` → `"Does not apply"`, `"."` → `NaN`, `COUNTRY_MAP`, ordered categoricals, the `Age_Median` remap) that would mask real disagreements and manufacture artefactual ones. Comparing raw keeps decision 3's promise: an exact cell-for-cell diff with no value-translation layer.

---

## 2. Field crosswalk

**Almost every mapping is an identity mapping** — same column name, same value domain, same coding rule (decision 2). Column names carry over verbatim, including `Clincial Trial YN`, `Funding/COI YN`, `Citation/Title`, `Retention (%)`, `Followup in months`, `Implementation Outcome`, `Double+Blind`, `Pos Result Y/N`. Binary variables stay numeric `1`/`0`/`3`/`"."` on both sides (decision 3). Stated once; only the exceptions are enumerated below.

### 2.1 Exceptions — name changes

| Old | New | Note |
|---|---|---|
| `Retention` (Smoking file only) | `Retention (%)` | Canonical spelling. `_lib.clean()`'s rename branch becomes dead code. |
| `StudyDesignType` (Smoking file only) | — | Column dropped; see 2.3. |

### 2.2 Exceptions — value normalizations

| Column | Old values | New values | Note |
|---|---|---|---|
| `Condition` | `Alcohol` (33), `Smoking` (4), `Opioids` (7) | `Alcohol`, `Smoking`, `Opioid` | Value normalization, **not** a column rename. The Opioid file stores the plural. Comparison maps `Opioids` → `Opioid` before diffing. |
| `Country_USvsNonUS` | `US` (16), `NonUS` (23), `Both` (1), `USA` (3), `.` (1) | `US`, `NonUS`, `Both`, `.` | `USA` → `US` normalized before diffing; both were already collapsed to `US` by `COUNTRY_MAP` downstream, so no information moves. |
| `Age_Median` | `<30`, `30-50`, `50+`, `.`, and the raw numerics `48.5` (×1), `51.0` (×3) | closed enum only | The four numerics currently become `NaN` at clean time. New values are the bracket. Reported as **corrected old miscode**, not as disagreement. |
| `BaseStatus` | `Severe`, `Moderate`, `Mild`, `.`, and `1` (×2) | closed enum only | Same treatment; the two `1`s currently become `NaN`. |

### 2.3 Exceptions — structural

| Change | Detail |
|---|---|
| **Three files → one table** | Per-file separation is replaced by the `Condition` column (decision 1). The per-condition scripts filter on it; their `--condition` flag and output paths are unchanged (decision 7). |
| **`url or link to pdf` dropped** | Populated in all 44 frozen rows, no counterpart in the new master. Not consumed by any script. Retained in the frozen files if ever needed. |
| **`Study Design Type` dropped** | Held the constant `"Clinical Trial"` in all 44 rows across all three files — zero information. Consumed by exactly one place: the Table 3 indicator "Study design type reported", which was therefore trivially 100%. That cell now renders `—` on existing grey styling with no code change; the heading's indicator count is off by one, flagged as an open question in `clinical_system_design.md` §9.2. |

### 2.4 Additions — no old counterpart

18 fields: `StudyID`; `EligibleYN`, `EligibilityFailedCriterion`, `EligibilityNote`; `SafetyReported`, `AnyAEReported`, `NumDistinctAEs`, `NParticipantsWithAE`, `AE_denominator`, `ArmScope`, `WorstSeverity`; `text_source`, `text_format`, `SourcePDF`; `Model`, `PromptVersion`, `RubricVersion`, `Temperature`. Plus the entire `ae_events` table and `rationale_log.md`.

These are reported as coverage statistics (how many rows carry each) and are not compared. One exception: `SafetyReported` **is** compared against old `HarmsAssessed` under the equivalence `SafetyReported = Y` ⟺ `HarmsAssessed = 1`, because it is the same fact in a different convention and a disagreement there is a real recoding of harms.

## 3. Row identity

**Join key: `(first_author_surname(Citation/Title), Year)`** — the same tuple that keys `EFFECT_SIZE_EXTRACTIONS`, `CONVERSION_RULES`, and `TIER2_RATINGS`. Derived identically on both sides by `_lib.first_author_surname()`, which splits on the first `,` or `;` and normalizes curly apostrophes and non-breaking hyphens. Using the config key rather than a new one means a successful join is simultaneously proof that the config lookups still resolve.

| Case | Handling |
|---|---|
| Exact tuple match | Matched. Expected for 44 rows. |
| Duplicate tuple on either side | **Blocked upstream** by the validation gate (`clinical_system_design.md` §1.3); the comparison never sees one. |
| Surname differs only by normalization (diacritics, `’`, `‑`) | Matched — `first_author_surname()` already normalizes these. |
| Surname differs by initials (`Johnson` vs `Johnson MW`) | **Not** auto-matched. Initials are part of the key by design (`_config_smoking.py` keys `('Johnson MW', 2026)` and `('Johnson', 2016)` separately). The manifest freezes the old surname token and the gate enforces it, so this should not occur; if it does, it is reported as a near-miss. |
| Same surname, `Year` differs by ±1 | Reported as a **near-miss requiring human confirmation**. Never auto-merged — an online-first/issue-year difference and two genuinely different papers by the same author look identical to a matcher. |
| Old row with no new counterpart | **Blocking** — data loss (§6, error class E1). |
| New row with no old counterpart | Reported as **expected** if the `StudyID` is one of the four previously dropped alcohol studies named in `reconciliation_report.txt`; otherwise a near-miss for human review. |

## 4. Comparison procedure

For each matched study, every comparable field is checked and assigned an agreement verdict. Agreement is defined per type.

| Type | Fields | Agreement rule |
|---|---|---|
| Binary (numeric-coded) | the 39 names in `_lib.BINARY_COLS` | **Exact.** `1`≠`0`≠`3`≠`"."`. No tolerance — these are the cells that drive Tables 2, 3, and 4. |
| Closed enum | `BaseStatus`, `Age_Median`, `Country_USvsNonUS`, `Condition` | **Exact after the §2.2 normalizations.** |
| Integer | `Year`, `SampleSize_NFinal` | **Exact.** Any difference is an error class (§6). |
| Percent | `Retention (%)`, `PercentFem`, `RaceEthnicity_BIPOCPercent` | **±1.0 percentage point.** Justification: `clean()` already rounds `Retention (%)` to 1 dp, and two processes computing `completers/denominator` from the same counts can differ by rounding or by an enrolled-vs-randomized denominator choice. 1 pp is below the resolution of every downstream use — Table 1's mean (SD) and Table 3's `reported` proportion — with one carve-out below. |
| Percent, threshold carve-out | `Retention (%)` | Any difference that moves the value across **80%** is escalated regardless of magnitude, because it flips a Table 2 and Table 3 cell. A 79.6 → 80.1 change is within tolerance numerically and out of tolerance analytically. |
| Continuous months | `Followup in months` | **±0.5 months**, matching the codebook's own conversion granularity (2 weeks = 0.5). Any difference crossing a **Table 5 bin boundary** (1, 3, 6, 12, 24) is escalated regardless of magnitude. |
| Free text | `Citation/Title`, `InterventionDescription` | **Semantic, not string.** Compared on content: for `Citation/Title`, whether the surname token, year, journal, and title refer to the same article; for `InterventionDescription`, whether substance, route, dose, and session structure agree. Differences in wording, abbreviation, or word order are agreement. A changed substance, dose, or route is a disagreement. |
| Effect-size text | `Outcome`, `SD`, `PVal` | See §5. |

**Report.** `old_new_comparison_report.md` contains:

1. **Roster** — matched (n), new-only (n, listed), old-only (n, listed), near-misses (listed).
2. **Per-field agreement table** — one row per column: n compared, n agree, n disagree, agreement rate, and the disagreement class breakdown.
3. **Per-study disagreement listing** — for every disagreeing cell: `StudyID`, field, old value, new value, assigned class, and the new row's `rationale` entry for that field where one exists. The rationale is the reason this comparison is adjudicable at all; the old side has none.
4. **Class counts** — the §6 taxonomy with a count per class, so the reviewer sees the *shape* of the disagreement rather than a flat list of 1,700 cells.
5. **Tier-1 block** — §5.
6. **Verdict** — pass / fail against §7.

## 5. Effect-size fields — the tighter standard

`Outcome`, `SD`, `PVal`, and `SampleSize_NFinal` determine forest-plot position, so they are not compared as text at face value. They are compared **at the level of the quantity they produce.**

**Procedure.** Run `_lib.build_results()` against both the frozen cleaned frames and the new cleaned frames, using each side's own config entries, and compare the resulting plot frames on the join key.

| Check | Standard | On failure |
|---|---|---|
| `metric` family | Same conversion family (`d`/`g`, `eta_p`, `F`, `chi2`, `OR`/`RR`, proportions, none) | **Escalate** — the study's evidence was reinterpreted, not re-transcribed. |
| `confidence` band | Identical (`clean` / `approx` / `excluded`) | **Escalate** — the marker changes from filled to hollow or leaves the plot entirely. |
| `g` | **\|Δg\| ≤ 0.05** for studies where both sides produce a value | **Block** above 0.05. |
| `SampleSize_NFinal` | Exact | **Block** on any difference. |
| Sign of `g` | Identical | **Block** on a flip. |

**Why 0.05 on `g`.** The forest plots tick the x-axis at 0.5-unit intervals and draw reference lines at 0.2 / 0.5 / 0.8. A 0.05 shift is below the visual resolution of the rendered marker and far below the narrowest CI half-width in the current tables, so it cannot move a reader's interpretation. Anything larger visibly moves a marker, and a visibly moved marker without an identified cause means the two extractions disagree about the study's result.

**What blocks acceptance of the new dataset:** any `|Δg| > 0.05`, any sign flip, any `SampleSize_NFinal` difference, on any matched study. Each must be resolved — by identifying which side is wrong against the source PDF and correcting the new side, or by documenting a ratified adjudication that the new side is right and the old was wrong. A `metric`-family or `confidence`-band change is escalated for human reading but does not block on its own, since a legitimate re-reading of a study (finding the df that the old extraction lost, for instance) properly moves a study from `excluded` to `approx`. That improvement is exactly what the redesign was for — it must be *seen*, not prevented.

## 6. Disagreement taxonomy

Every disagreeing cell is assigned exactly one class. Classes X1–X5 are expected and are not defects. Classes E1–E4 are errors and must be investigated before acceptance.

### Expected — not errors

| Class | Description | Evidence that places a cell here |
|---|---|---|
| **X1** | **No old counterpart by construction.** The four previously dropped alcohol studies. | `StudyID` appears in `reconciliation_report.txt` as `NEW` and in `expected_missing.csv` context. Not compared at all; counted separately. |
| **X2** | **Old row flagged ineligible by the new screen.** A finding *about the old dataset*, not a migration defect — the old process had no eligibility criterion, so an ineligible study could enter unremarked. | `EligibleYN = N` with a completed `EligibilityNote`. Reported prominently: each one is a candidate correction to the published evidence base. |
| **X3** | **Corrected old miscode.** The old value is invalid under its own codebook. Known instances: `Age_Median` numerics (4 rows), `BaseStatus = 1` (2 rows), all of which currently become `NaN` at clean time and are counted "Not reported" in Table 1. | Old value outside the field's documented domain; new value inside it. |
| **X4** | **Old blank, new filled.** A field the hand extraction left `"."` that the new one populates. | Old is `"."`/`NaN`, new is a value, and the new row's `rationale` cites a source passage. Expected to be common for `Retention (%)`, `RaceEthnicity_BIPOCPercent`, and `PercentFem` in the pre-1980 stratum. |
| **X5** | **Genuine judgment difference on an ambiguous article.** Two defensible readings of an underspecified report. | The new row carries a `rationale` entry that engages the ambiguity, and the field is one of the twelve methodological-quality judgments or a boundary-case binary. **Requires the rationale to exist** — an unexplained difference is not X5, it is E4. |

### Errors — must be investigated

| Class | Description | Why it is an error |
|---|---|---|
| **E1** | **A matched old row is missing from the new master.** | Data loss. Blocks at the reconciliation gate before comparison. |
| **E2** | **A flipped binary** — `1`↔`0` on any of the 39 `BINARY_COLS` names, with no supporting rationale. | These cells are the substance of Tables 2, 3, and 4. A flip changes a published percentage. (`1`↔`3` and `0`↔`"."` are convention shifts, classed X5 when explained, E4 when not.) |
| **E3** | **A changed sample size or effect size** — `SampleSize_NFinal` differing at all, or `\|Δg\| > 0.05`, or a sign flip. | Moves a forest-plot marker. See §5. |
| **E4** | **An unexplained disagreement.** Any cell that fits no X class and carries no rationale entry. | The residual bucket. Its size is the honest measure of how much of the disagreement the pipeline cannot account for, and it is the number a reviewer should look at first. |

**Report counts per class, per condition and overall.** A reviewer reading "X4: 61, X5: 22, E2: 0, E3: 0, E4: 3" learns the migration's shape in one line; a flat list of 1,700 cells teaches nothing.

---

## 7. Acceptance criteria

The new dataset is accepted as a successful migration when all of the following hold:

1. **Roster complete.** Zero E1. Every frozen row matched, or listed in `expected_missing.csv` with a human-authored reason. Every new-only row is one of the four X1 studies or has a human-confirmed near-miss resolution.
2. **Tier-1 clean.** Zero unresolved E3. Every `|Δg| > 0.05`, sign flip, and `SampleSize_NFinal` difference either corrected against the source PDF or closed by a ratified written adjudication naming which side is right.
3. **Binaries clean.** Zero unresolved E2.
4. **Everything classified.** Zero E4 outstanding. Each residual cell is either reclassified into an X class with a rationale, or promoted to E2/E3 and resolved.
5. **Figures explained.** The visual-regression check (`clinical_system_design.md` §9.2) reports an empty "unexplained" column, and every explained difference maps to an entry in the row-set diff.
6. **Validation gate clean.** `validation_report.txt` shows zero blocking failures; every warning has been read and either accepted in writing or acted on.

**Advisory, not a gate: overall exact agreement on binaries and enums.** With 44 matched studies × ~45 comparable fields ≈ 2,000 cells, the report prints the global exact-agreement rate. It is a **systematic-drift detector, not a quality bar**: below roughly 90%, the disagreement is unlikely to be 200 independent judgment calls and is more likely a convention shift — a `3`-vs-`"."` divergence applied corpus-wide, say, or an eligibility criterion changing how a whole class of study is coded. In that case, diagnose the convention and re-run, rather than adjudicating cells one at a time. Above it, per-cell adjudication is the right tool. No specific rate constitutes acceptance on its own; criteria 1–6 do.

**What the reviewer does with the residue.** Every X2 (an old row now judged ineligible) and every X3 (a corrected old miscode) is a **finding about the published evidence base**, not migration bookkeeping, and belongs in the manuscript's limitations or a data-corrections note — they are the concrete answer to "what did the ad-hoc extraction get wrong." Every X5 is a documented judgment call whose rationale is now archived, which is precisely the auditability the old process lacked. X4 is reported as a coverage improvement with a per-field count. The one thing the reviewer must not do is let an E4 be quietly reclassified as X5 without a rationale entry to support it; the rationale requirement is what keeps the taxonomy from absorbing errors.
